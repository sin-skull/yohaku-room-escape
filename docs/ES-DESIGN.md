# ES図 — 行動・発見・感情

この計画の「ES図」は、プレイヤーの行動・発見・感情を重ねる体験設計図として暫定的に扱う。業界共通の用語と断定しない。感情は設計意図であり、実測結果ではない。

```mermaid
flowchart LR
  enter["和室に入る・落ち着く"] --> look["見回す・気になる物を探す"]
  look --> focus["触れて寄る・もっと見たい"]
  focus --> high["神目線で俯瞰・墨が三に揃う"]
  focus --> eye["歩行視点で覗く・墨が一に揃う"]
  high --> ink["発見を写す・自分で見つけた実感"]
  eye --> ink
  ink --> lattice["松の行・竹の列を対応させる"]
  lattice --> flower["格子が開く・梅の五弁を発見"]
  flower --> match["松竹梅の錠へ対応づける・仮説"]
  match --> turn["数字を上下に回す・試す"]
  turn -->|"違う組み合わせ"| retry["動かない・観察し直す"]
  retry --> ink
  turn -->|"対応が合う"| drawer["引き出しが開く・納得"]
  drawer --> key["鍵を手に取る・前進"]
  key --> door["襖が開く・解放"]
  door --> after["余韻・誰かに話したい"]
  look -.-> hint["自分でヒントを開く"]
  retry -.-> hint
  hint -.-> ink
```

| 場面 | 美術の必要性 | 観察で確かめること |
|---|---|---|
| 全景 | 畳・障子・床の間で向きと注目箇所をつくる | 説明なしで最初の調査へ進めるか |
| 飾り棚・覗き棚 | 高さ・奥行き・遮蔽物が墨の見え方を変える | 視点を変えて線が揃うことに気づくか |
| 掛け軸・格子 | 松↓竹→の意匠で行と列の対応を示す | 二つの発見を組み合わせられるか |
| 覚え書き | 自分で写した情報だけを墨字で残す | 記録・見返す操作が分かるか |
| 箪笥 | 木の錠、刻印、引き手で操作を示す | 上下・タップ・引く操作が分かるか |
| 正解 | 引き出しと音の変化が因果を返す | 正解した理由と結果が伝わるか |
| 不反応 | 和紙の短い墨書きで応答する | 操作失敗と無反応な物を区別できるか |
| 脱出 | 襖の開閉と光で終わりを示す | 達成と余韻を感じるか |

## 実装上の状態

```mermaid
stateDiagram-v2
  [*] --> 探索
  探索 --> 松竹観察 : 俯瞰または覗きの位置を合わせる
  松竹観察 --> 手がかり記録 : 写す
  手がかり記録 --> 格子開放 : 松の行と竹の列を選ぶ
  格子開放 --> 梅記録 : 花紋を見て写す
  梅記録 --> 錠操作 : 箪笥を調べる
  手がかり記録 --> 錠操作 : 箪笥を調べる
  探索 --> 錠操作 : 箪笥を先に調べる
  錠操作 --> 錠操作 : 不正解・数字変更
  錠操作 --> 引き出し開 : 正解して引く
  引き出し開 --> 鍵所持 : 手に取る
  鍵所持 --> 鍵選択 : 持ちものの鍵をタップ
  鍵選択 --> 鍵所持 : 同じ鍵を再タップ
  鍵選択 --> 襖開閉中 : 襖をタップして使う
  襖開閉中 --> 脱出 : 開く動きが完了
  脱出 --> 探索 : もう一度
```

ヒントは進行状態を勝手に変更しない。閉じる・拡大・見回す操作でも手がかりや数字を失わない。既存の進行保存を引き継ぐ。

v1.3.0の視点謎は[実装と検証](VIEWPOINT-PUZZLES.md)、歩行／神目線・選択操作は[操作仕様](CONTROLS.md)を参照。制限時間はない。館版では、各主要部屋の松・竹・梅の最終解を玄関へ集約する。[館の構成](MANSION.md)は現行の一部屋の実装と区別する。
