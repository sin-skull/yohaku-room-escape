# 技術と体験の改善記録

2026-10-22：機能テストの成功を、初見の理解・楽しさの評価と分離する。[再設計R2](REDESIGN-R2.md)で操作と謎を見直す。以下の機能・性能の履歴は引き続き技術記録であり、人の試遊合格ではない。

2026-10-21。性能目標と確認済みの結果を区別する。

v1.2.0では歩行／神目線の切り替え、四方の壁と天井、家具の当たり判定とタップ接近、収納式の持ちもの欄、選択して対象に使う操作を追加。[操作仕様](CONTROLS.md)を参照。神目線では手前の壁を表示上だけ隠し、歩行時の衝突を残す。

| 問題 | 今回の変更 | 残る確認 |
|---|---|---|
| HTMLの説明欄が部屋より目立つ | 全画面の3D、最小限の持ちもの、墨書きの和紙、木製錠へ変更 | 初見の人が操作を見つけられるか |
| 固定の見回し倍率 | ホイール・ピンチ・拡大縮小ボタン、物への注視、全景復帰 | 実機のピンチ、壁や家具の遮蔽 |
| マーカーがドラッグを受け取れない | 共通のポインター処理でドラッグと調査を分離 | 指の追加・中断・画面外への操作 |
| 三桁錠が標準セレクト | 0〜9の循環、タップ、上下ボタン、スワイプ、キーボード、読み上げ属性 | 高齢者・小さな画面での操作性 |
| 謎を解く前に文章が関係を明かす | 草木の数と刻印の対応に変更。通常の誘導文を撤去 | 墨絵が同じ種類と認識されるか |
| 正解時の画面が動きを隠す | 引き出しは閉じる画面の後で動く。襖は開閉完了を待って終了表示 | 背景タブから戻った際の完了処理 |
| 比較時に注視位置が変わる | 比較条件を全景に揃え、終了後の視点・倍率・注視点を復帰 | 実機の計測を追加 |

輪郭・奥行き・引き出し・襖・鍵は立体のまま。7素材を1枚の1024px WebPへまとめ、各素材の部分は最大500px。共有アトラスは約16KB。動的な影・物理演算は使わず、必要な動きの間だけ再描画する。描画倍率は最大1.5。

## 既存の比較記録

`tools/texture-pilot-results.json` は、デスクトップの同一部屋を同条件で比較した試験記録。

| 記録値 | 立体細部中心 | 画像中心 |
|---|---:|---:|
| 三角形 | 34,572 | 19,908 |
| 描画回数 | 107 | 89 |
| テクスチャ展開量概算 | 11.25MB | 9.92MB |
| CPU描画送信中央値 | 1.7ms | 1.2ms |

鍵取得後・引き出し開の状態での過去の単一比較。今回の全画面UI変更後の実機FPSを示す値ではない。CPU描画送信時間からGPU処理時間やFPSを推定しない。設定の「素材の比較」で同じ条件のA/Bを残している。

この表は旧版の記録であり、v1.2.0の四方の壁を含む現在の描画数ではない。現在の比較は両方式とも同じ室内位置・視点の動きで測定し、終了後に歩行／神目線・位置・向きを復帰する。

## 実機の性能予算（未達成確認）

- 初回操作可能まで5秒以内：10Mbps、往復100msの条件を固定して測る。
- 初回の必須通信1.5MB以内：コード・画像・必要フォントを含める。現行は外部フォント通信を撤去。
- 見回し中のフレーム間隔p95を33.3ms以内：iOS Safari、Android Chromeの実機で測る。
- 画像中心の全景で三角形25,000以下、描画回数100以下、画像展開量12MB以下を予算とする。
- 試験対象候補：iPhone SE第2世代相当と4GB級Android。実際の機種・OS・温度・設定を記録してから判定する。

## 今回の確認

`npm run check` と `npm test`。入力テストは数字循環、倍率の限界、マーカーのタップとドラッグ、ピンチ後の誤タップ抑制、キャンセルを対象にする。ブラウザで掛け軸→錠→鍵→襖→脱出を操作する。画面幅の模擬確認は、実機のタッチ操作試験の代わりにはしない。
