# 視点を使う謎 — v1.3.0の一部屋試作

神目線と歩行視点を「同じ空間を違う読み方で見る」遊びにする。切り替えだけで答えの画像を差し替えず、奥行きや遮蔽物そのものが見え方を変える。

## 現在遊べる流れ（解答を含む）

1. 高い飾り棚へ寄り、神目線の「俯」で上から見る。高さの違う九つの墨の断片が「三」に揃う。松の手がかりとして写す。
2. 歩行視点で床の印から覗き棚を調べる。奥行きの違う三つの墨が「一」に揃う。竹の手がかりとして写す。屋根と側面が上からの視線を遮る。
3. 掛け軸と格子の「松↓・竹→」を対応させ、上から三段目、左から一つ目を押す。木の覆いが上がり、五弁の梅を見つける。誤答しても最初からやり直さない。
4. 発見した三・一・五を箪笥の松竹梅の錠へ入力する。引き出しから鍵を取り、持ちもの欄で選択して襖へ使い、脱出する。

掛け軸と覚え書きは、最初から答えを一覧表示しない。観察できる位置では和紙の「写す」が現れ、押した情報だけを保存する。アイテム欄で覚え書きを選び、目の印から拡大して見返せる。通常の反応は短い墨書きと物の動きで伝え、説明が必要ならヒントボタンから段階的に読む。

制限時間は入れない。秒数制限の仕掛けは制作の最後に検討し、現在の謎や保存に時間切れのリセットを設けない。

## 実装と検証

- 棚の墨は異なる高さ・奥行きの実際の3D面。神目線では手前の壁を隠し、歩行視点では壁・天井・遮蔽物を残す。
- 木目などは既存の共有画像を使い回す。新しい花紋は256pxの画像、格子はInstancedMeshでまとめ、棚は既存の静的結合処理に含める。リアルタイム影と物理演算は追加しない。
- 視点の位置と方向には許容範囲を設け、狭い一点を探す操作を要求しない。発見済みの「写す」は繰り返し表示しない。
- 観察、花紋の開放、錠、取得アイテム、脱出を保存する。旧版で錠を解いた保存はその進行を保つ。旧版で掛け軸だけ見た保存には未発見の解を付与しない。
- 自動テスト19件とデスクトップブラウザで新規の発見から脱出、途中保存からの復帰を確認。スマホ幅の表示確認は実機での操作・性能評価の代わりにはしない。

## 次の判断

初見の人に「どちらの視点で何を探せるか」「墨が揃った瞬間」「行と列の対応」が伝わるかを観察する。棚に寄る操作と視点切り替えが分かりにくければ、美術の目印や操作を調整する。館へ広げる前にこの一部屋で確かめる。

館・廊下・三つの主要部屋と30段階の依存関係は引き続き設計案。今回の315を完成版の最終解として固定しない。
